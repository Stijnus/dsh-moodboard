## Findings (ordered by severity)

### F1 — Low/Medium — modal focus trap could be escaped with the keyboard — **FIXED & re-verified**

**Original defect (first pass).** The Tab trap lived only on the overlay's
`onKeyDown`; the document-level keydown effect handled Escape only, so a Tab
dispatched while focus sat on `<body>` (after clicking non-focusable dialog
padding) bypassed the trap and landed on page chrome behind the modal. Reproduced
in Chromium against a replay of the handler logic (`activeElement === BODY`,
`Tab` → outside button, `inDialog=false`). CONTRACT (`docs/CONTRACT.md:720-722`)
requires the dialog to be "focus trapped".

**Fix (verified).** `client.js:3710-3737` extracts `trapFocus(event)`; the
document-level keydown effect (`client.js:3522-3539`) now handles `Tab` →
`trapFocus` as well as Escape; the overlay handler (`client.js:3738-3746`)
delegates to the same helper. The exact real-dialog Chromium matrix is in
"Re-verification after fixes": blank-padding click → `BODY`, then `Tab` → focus
inside; 15-Tab cycle stays inside; Shift+Tab from body inside; wrap preserved;
Escape closes once from inside and once from `BODY`. No residual impact.

### F2 — Low/Medium — direct image URLs with a non-`image/*` content type failed above 4 MiB — **FIXED & re-verified**

**Original defect (first pass).** `captureOne` chose the read cap from the response
`content-type` before the bytes were read (`image/*` → 12 MiB, everything else →
4 MiB), so a 5 MiB PNG served as `application/octet-stream` failed as
`upstream-error` "The response is too large to read" before the signature-based
direct-image branch could run — even though the contract treats signature-matched
bytes as a direct image and caps images at 12 MiB (`docs/CONTRACT.md:532-533`,
`:543-546`).

**Fix (verified).** `sources.js:1218` now uses `MAX_PAGE_BYTES` only for declared
HTML/XML types and `MAX_IMAGE_BYTES` otherwise; after classification,
`sources.js:1254-1256` rejects non-HTML bodies above `MAX_PAGE_BYTES` with
`upstream-error` "The page is too large to read.", so both documented caps still
hold. Re-verification (see above): octet-stream / `binary/octet-stream` /
no-content-type 5 MiB PNGs import; oversized HTML still fails; declared caps and
normal capture unchanged. Regression test: `test/sources.test.mjs:495-519`.

### F3 — Low — IPv6 transition ranges were not classified as private — **FIXED & re-verified**

**Original defect (first pass).** `isPrivateIPv6` handled loopback/unspecified, ULA,
link-local, multicast and IPv4-mapped/compatible forms, but not the IPv6→IPv4
transition prefixes (`64:ff9b::/96`, `64:ff9b:1::/48`, `2002::/16`, `2001::/32`),
so on NAT64/6to4/Teredo networks a link such as `http://[64:ff9b::a9fe:a9fe]/`
could reach `169.254.169.254` / `127.0.0.1` past the SSRF gate (probe: fetch was
attempted for both NAT64 forms).

**Fix (verified).** `sources.js:491-505` now decodes the embedded IPv4 for
`64:ff9b::/96` (private/reserved embedded → reject), rejects `64:ff9b:1::/48`
whole, decodes `2002::/16`, and blocks Teredo `2001:0::/32`, documentation
`2001:db8::/32` and `100::/64` whole. Re-verification: all 13 transition/reserved
cases are blocked before fetch; public IPv6, public NAT64 and public 6to4
addresses are still attempted (no over-blocking). Regression test:
`test/sources.test.mjs:561-586`.

### F4 — Low (contract drift) — `captureReferences` documented `tags`/`notes` options — **FIXED**

## Confirmed good (audited, not assumed)

**SSRF / source safety (sources.js)**
- Only `http:`/`https:`; length ≤ 2000; embedded username/password rejected
  (probe: 19 blocked shapes, fetch never called for any).
- Rejects `localhost`, `*.localhost`, `*.local`, `*.internal`, IPv4 private/loopback/

  IPv6 loopback/ULA/link-local/multicast and `::ffff:` mapped forms (both dotted and

## Residual risks / untested areas

1. **DNS rebinding (TOCTOU).** The SSRF gate resolves the host with `dns.lookup`
   (`sources.js:885`, `:950`) but the actual connection is made by the global `fetch`,
   which resolves again. A malicious authoritative DNS with TTL 0 can answer public on
   the check and private on the connection. The CONTRACT-mandated check is satisfied;
   fully closing this needs a pinned-address connect (e.g. undici `Agent` `connect`
   lookup) or verifying the peer address after connect. Same applies to every redirect
   hop and to provider image/preview URLs.
2. **Memory/DoS shape.** Drafts are collected before the serialized save
   (`index.js:1125-1135`): worst case 20 × 12 MiB = ~240 MiB of image bytes plus page
   bodies per request, and concurrent imports collect in parallel (only the save is
   serialized). Contract caps each item, not the batch; consider a batch byte budget.
3. **No overall batch deadline.** 20 sequential URL captures can occupy one HTTP
   request for minutes (15 s page + image each); the client `busy` state cannot cancel
   the POST, and closing the dialog leaves it running (harmless but confusing).
4. **HTML metadata parsing is regex-based.** Meta tags inside HTML comments or
   `<script>` strings can be picked up as the preview image/title (wrong preview,
   cosmetic; no code execution). No `<base href>`, `srcset`, or lazily-loaded image
   resolution — by design (`no-preview-image` fallback).
5. **Live provider behaviour unverified.** No network/key in this environment: Mobbin
   and Are.na request/response shapes are verified only against the documented contract
   and injected-fetch unit tests; a real 200 response schema change cannot be exercised
   here. `Retry-After` handling is unit-tested but not seen end-to-end through the HTTP
   route.
6. **Viewport/rendering of the dialog not screenshot-verified.** The panel is a
   hand-written browser module; this review verified structure/CSS/classes/a11y wiring
   and the keyboard mechanism, not visual layout at mobile widths (there is a
   `@media (max-width: …)` full-height dialog rule at `client.js:2302`).
7. **`captureReferences`/`discoverReferences` throw batch-shape `SourceError`s with
   item codes** (`invalid-url`/`invalid-path`) when called directly; unreachable through
   the Host (which validates first), but a library consumer mixing them up would see an
   odd code.
8. **File-mode permissions.** On disk, `sources.js` and `docs/INSPIRATION-WORKFLOW.md`
   are currently `0600` in the working tree (git tracks only the exec bit, so a commit
   normalizes this); no functional impact.
